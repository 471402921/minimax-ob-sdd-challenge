## 1. 三类凭据不能混用

| 用途 | 本机私密配置 / 变量 | 使用范围 |
| --- | --- | --- |
| OB 平台查询、领取、回传 | `~/.config/minimax-ob-judge/platform.env` → `OB_JUDGE_TOKEN` | 控制层；不得传给 Harbor 审阅 Agent |
| MiniMax M Plan 模型调用 | `~/.config/minimax-ob-judge/mplan.env` → `OB_EVAL_MODEL_KEY`；另映射 `MINIMAX_CN_API_KEY` | 独立评测模型，不读取当前 Pi auth |
| 私有 Git 仓库读取 | 平台任务中的凭据或用户明确授权的仓库凭据 | 只交给取代码进程；不进 prompt、argv、Git 配置和日志 |

两个 env 文件是用户有意保存的本机秘密：目录权限 `700`、文件权限 `600`，不在仓库内。
脚本不自动加载这些文件；每次运行需显式 `source`。不要 `cat`、`echo`、`env` 输出密钥。
也不要 `sudo -E` 转发整个宿主环境。

**另一个终端执行 export 不会改变已经运行的 Pi 进程。** 启动子进程时加载私密文件即可，
无需把密钥贴进聊天。`echo "保存成功"` 不是验证，必须实际检查变量非空和接口响应。

### 安全配置/轮换 OB Token（完整复制到 Bash）

```bash
(
  set +x
  umask 077
  read -r -s -p "粘贴 OB 评分平台 Token（不回显）: " value || exit 1
  printf '\n'
  [ -n "$value" ] || { echo "空值，未保存"; exit 1; }
  install -d -m 700 "$HOME/.config/minimax-ob-judge" || exit 1
  printf 'export OB_JUDGE_TOKEN=%q\n' "$value" > "$HOME/.config/minimax-ob-judge/platform.env" || exit 1
  unset value
  chmod 600 "$HOME/.config/minimax-ob-judge/platform.env" || exit 1
  unset OB_JUDGE_TOKEN
  source "$HOME/.config/minimax-ob-judge/platform.env" || exit 1
  [ -n "${OB_JUDGE_TOKEN:-}" ] || exit 1
  echo "保存和本地载入成功；尚未验证平台鉴权。"
)
```

`printf` 和 `>` 必须是同一条命令；若手动换行必须有续行符。不要将上述括号省掉后逐行
执行，否则前面的错误不一定阻止后续命令。M Plan 的配置方式相同，但变量和文件名见表格，
不要把模型订阅 Key 当成 OB 评分 Token。

## 2. 平台实时积压查询（只读）

新版 skill 已确认并同步：

- 仓库：`PsiACE/powercontext-2026`（私有）
- 分支：`2026-competition-platform-review`
- 路径：`skills/techcamp-platform-integration/`
- 固定提交：`e79431254ee6b7e1a1c1f6da716dae8c335987a8`
- 新命令：`queue-count`、`queue-count --all-questions`
- 接口：`POST /queryTaskQueueCount`；沿用 OB 评分凭据，JSON body 传凭据及可选一级题号。

在仓库根目录执行以下命令。仅把平台凭据交给计数客户端，不调用领取/回传接口：

```bash
(
  set +x
  source "$HOME/.config/minimax-ob-judge/platform.env" || exit 1
  : "${OB_JUDGE_TOKEN:?缺少 OB 平台 Token}"
  export PLATFORM_TOKEN="$OB_JUDGE_TOKEN"
  export PLATFORM_QUESTION_ID=600077
  export PLATFORM_BASE_URL=https://openwebapi.oceanbase.com/api/techcamp/testplatform/taskrecord
  uv run --no-project \
    --with httpx==0.28.1 \
    --with pydantic-settings==2.15.0 \
    python skills/techcamp-platform-integration/scripts/platform_client.py \
    --env-file /dev/null queue-count
)
```

`--env-file /dev/null` 防止误读工作目录中的 `.env`；`PLATFORM_QUESTION_ID` 显式限定我们
负责的 MiniMax 一级题。不要改成子题 `800514`。正常输出含 `questionId/waitCount/runCount`。

| 字段 | 精确口径 |
| --- | --- |
| `waitCount` | 授权及筛选范围内、符合配置且未删除的待执行任务条数（状态 0） |
| `runCount` | 同范围的执行中任务条数（状态 1），**包含超时但尚未结束的任务** |

- 是提测任务数，不是队伍数、学生人数、子题数或评分机实际进程数。
- 完成、失败、取消、删除任务不计入。一个任务有多个子题仍只计一次。
- 不领取、不锁定、不续租、不改重试次数；数量是瞬时快照，不保证下次领取拿到任务。
- `--all-questions` 省略题号，仅统计当前凭据授权范围，**不是全平台**。
- 有效凭据查询未授权/不存在/内置核验题可返回两个 0，因此“0”不证明该题全平台无任务。
- HTTP 成功、业务 `code=200` 且两值为非负整数才算成功。404、鉴权失败、超时及异常数据
  是“查询失败”，不是零积压。服务端需部署包含 `obtechcamp 6eebe74` 的版本。
- 如果需要监测，按 30–60 秒间隔并对错误退避；当前不启自动轮询。

完整协议在已授权本机的 `skills/techcamp-platform-integration/references/platform-contract.md`。
该skill为私有上游快照，已gitignored，不随公开仓库分发；公开clone需另行合法获取才能运行上述命令。
**历史“没有计数接口”的判断已过期。** `submissionOptions` 仍只查询题目能力，不是计数。

## 3. 区分三种“查询”

| 操作 | 实际含义 | 是否领取 |
| --- | --- | --- |
| skill `queue-count` | 平台实时积压，需评分凭据 | 否 |
| `./judge/review.sh list` | 本机已领取未回传/已回传记录，不代表平台全队列 | 否 |
| `./judge/review.sh check` | 本地预检、旧的无交集题号探测、只读 submissionOptions；**目前不含计数** | 无交集探测预期不分配任务；它仍调用领取端点，不作为新计数方式 |

`check` 中的题目能力失败/配置偏差目前只报警，末尾“全部检查通过”不能覆盖中间警告。
后续可独立改造预检，但本次文档整理不改变脚本行为。

## 4. 人工审阅仍是正式入口

```bash
# 只在准备领取并有处理容量时运行；会提示确认，默认60分钟。
(
  set +x
  source "$HOME/.config/minimax-ob-judge/platform.env" || exit 1
  ./judge/review.sh fetch
)

# 看本机任务与剩余时限，不需要Token
./judge/review.sh list
```

- `review.sh` 默认 60 分钟；直接调用 `review.py` 的默认值是 30 分钟，不要混淆。
- 只评 `minimax/`；固定提交为平台 branch/commit 或领取时实际冻结的版本。
- 当前为 `600077/800514` 单子题固定分，当前满分 20；以每次任务 `maxScore` 为准，
  不是建议稿 60/25/15，也不能把满分硬编码到回传。
- 本机历史 `.submitted.json` 是回传证据。只有领取了任务、有实际审阅依据、时限有效，
  且用户明确授权结论后，才可调用 `review.sh submit`。不要把示例理由直接提交。
- 回传成功需要业务确认；网络不确定时冻结并原样重试，不能改理由/分数后碰运气。
  上游 skill 有 outbox；本地 `judge/review.py` 尚未完整接入，人工流程同样有这个风险。
- 平台错误、环境阻塞与选手功能缺陷分开记录，不把所有异常直接记作 0 分。

### 4.1 任务级仓库凭据留存与检出恢复

`review.py fetch` 在写入pending后、clone前，将仓库恢复URL与任务版本/租约绑定单独保存到
`~/.local/state/minimax-ob-judge/repo-credentials/`，按workdir散列和taskId分区。
目录700、文件600、原子替换；不含OB评分Token。普通claim、pending和日志仍脱敏。
可用 `OB_JUDGE_CREDENTIAL_DIR` 指定仓库/workdir之外的私密目录，拒绝软链接及错误所有者。

- clone中找不到完整SHA时，先用同一任务凭据定向fetch；认证/网络失败不等同于commit不存在。
- 私密保存失败则停止clone，保留pending并明确报错；任务已领取，仍需人工处理。
- 本地可恢复凭据存在且租约有效时，用 `python3 judge/review.py recover --task-id <taskId>`
  重试同一任务。新功能不能追溯恢复已丢失PAT；历史阻塞案例后来已取得替换授权并回传，不能再当当前待办。
- recover仅支持fetch_failed且有固定commit的任务；不领取、不回传、不续租，新的检出放在
  独立recovery目录，保留原失败现场。未冻结commit的任务需要人工确认，不能默默换HEAD。
- 只有回传业务成功且ACK的taskId匹配后，才进入本地_finish并清理任务凭据。确认不明确
  保留pending与凭据；清理失败会报警，不应因此重复回传。
- 过期但未确认终态的凭据不自动清理，避免丢失申诉/恢复能力；由操作者确认后处置。
- 此留存只接入人工review.py路径，旧run_judge.py尚未接入；不要据此开启旧自动判题入口。
- 不能将该私密目录挂载/复制进Harbor，也不要搜索或打印其中的凭据。

离线验证：`python3 -m unittest discover -s judge -p test_recovery.py -v`。

### 4.2 已核实仓库不可访问与过期回传

按[相对评分标准](相对评分标准.md)，用户/平台方已核实仓库确实不可访问可按0分回传：

```bash
# 仅Python CLI支持；理由写明核实来源，不声称执行过源码测试
python3 judge/review.py submit --task-id <taskId> --verdict fail \
  --confirmed-repo-unavailable --reason '已核实仓库无法访问，按确认规则判0分；未执行代码测试'
```

该例外仅用于fetch_failed/4，指定版本一致、有效租约且匹配ACK；一次网络/认证失败不自动成立。
其余未核实/裁判环境错误仍分开处理，不能一律判0。过期回传默认拒绝，平台方明确允许后才可
显式`--allow-expired`，不保证平台接受，也不作为批量调度策略。

## 5. Harbor 独立审阅

详见 [Harbor 运行说明](../harbor/README.md) 和 [实测记录](../harbor/VALIDATION.md)。
已完成真实任务审阅及独立后端补验；现有预热镜像、批运行和后台单任务服务。未接自动领取或回传。
批处理使用方法与边界见[批量评测运行器](批量评测运行器.md)。本机推荐：

```bash
# 已有固定任务快照和manifest后，先做资源与租约计划，再后台启动（不自动回传）
bash harbor/start_service.sh workdir/batch.json batch-UNIQUE
systemctl --user show harbor-batch-UNIQUE --property=ActiveState,SubState,Result
```

后台启动命令快速返回；40分钟wall上限不同于聊天等待时间。不要因用户询问耗时而中止。
读取该批state.json和Harbor result确认进度；重试必须保留旧产物且使用新batch ID。
以下run_pilot.py保留用于前台单次调试，不推荐在聊天工具内长时间阻塞：

```bash
# 仓库根目录；任务目录必须先经 prepare.py 生成。
(
  set +x
  source "$HOME/.config/minimax-ob-judge/mplan.env" || exit 1
  python3 harbor/run_pilot.py \
    --task 'workdir/harbor/review-<taskId>-<sha前12位>' \
    --model 'anthropic/MiniMax-M3.1-Flash' \
    --base-url 'https://api.minimax.cn/anthropic' \
    --api-format anthropic_messages
)
```

先把占位任务路径替换成实际已生成的目录。需要具有 Docker 权限的 worker；脚本不自动
sudo，本机直接运行会因 Docker 权限不足而受阻，不能把这当学生失败。

Harbor 中 `anthropic/` 是协议映射，实际请求发往 MiniMax 国内，不是 Anthropic 服务。
Pi 原生 provider 是 `minimax-cn`，原生 key 变量为 `MINIMAX_CN_API_KEY`。

**Harbor reward=1 仅代表报告协议/文件哈希校验通过，不代表选手通过或获得20分。**
判分校准、完整网络隔离、短期模型网关、自动租约调度、回传outbox和真实4路容量仍未完成。
`mplan.env`是沿用的文件名，不保证当前key仍为M Plan；套餐、QPS、token额度与机器trial容量分开核实。
