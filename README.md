# MiniMax × OceanBase SDD Challenge

面向软件持续演进的 SDD 上下文管理：赛题设计、OB 判题对接与 Harbor + Pi 审阅试点。

本仓库整理 MiniMax × OceanBase 2026 赛题的设计材料，围绕规格驱动开发（Spec-Driven Development，SDD），探讨如何让 AI 开发助手在需求变化、会话中断和任务交接后，持续完成符合当前规格的软件修改。

**运维文档更新：2026-10-29。** 赛题建议材料仍为 **v0.4 · 2026-09-14**，保留设计历史，
不等于已经冻结的生产评分规则。当前平台使用单子题二值计分（当前满分20，实际取任务maxScore）。

## 原始分层设计（历史建议，非现行平台分制）

- **基础（建议 60 分）**：找到有效规格及相关代码、测试，帮助现成 Agent 完成一次局部修改。
- **进阶（建议 25 分）**：处理规格变化，更新上下文并保留仍有效的约束。
- **挑战（建议 15 分）**：处理跨模块任务与会话接力，校验工程状态并改善运行效率。

工程知识的存储与混合检索建议使用 seekdb／OceanBase，任务记忆与上下文恢复建议使用 PowerContext。业务工程、开发 Agent 和 SDD 工具优先复用已有项目。

原始参考候选项目不代表已经通过赛事验收。现有审阅试点和单份作品复核也不能代替整体评测
准确性与容量校准；下一步与未完成项统一维护在 [当前状态](docs/当前状态.md)。
